# 元素手帐 · Elemental Journal

> 这个仓库（VCT）原本的定位是「新手的 vibe coding 试错与探索」，
> 元素手帐是其中攒得最完整的一个东西，所以直接放在根目录当主页。

> 一个**可以完全自由改**的个人手帐站：写在纸上的那种手帐，搬到了浏览器里。
> 同时有网页版（可直接挂 GitHub Pages）和桌面版（Electron，数据存本地、自带局域网聊天室）。

站点本身是**零构建的静态页面** —— 没有打包步骤、没有框架、没有依赖树。
HTML / CSS / 原生 JS 直接放在仓库里，克隆下来双击 `index.html` 就能跑。

## 它长什么样

- **首页**：全屏壁纸 + 横幅标题，往下是「记忆」段落 —— 一段滚动叙事的开场，滚到底会揭示一面照片墙
- **手记**：按时间归档的文章列表，可按分类与标签检索
- **作品集 / 项目**：做过的事（照片、菜谱、书单、手作），项目支持文字 / 图片 / 视频混排
- **游乐场**：贪吃蛇、俄罗斯方块、打砖块、记忆翻牌，四个能真的玩的小游戏
- **课表**：一天 11 节的课表，可增删改，也能导入 `.ics`
- **自述**：可以慢慢补完的自我介绍
- **友链**、**茶室**（局域网聊天室）

视觉上有两套语言：**手帐 / 漫画的纸感**（纸纹、胶带、拍立得、横格线），
和**七元素主题色系统**（一个 `--hue` 变量驱动全站配色，切换元素等于换主题）。

## 快速开始

### 网页版

最省事：

```bash
# 直接双击 index.html 也行 —— 只是聊天室会降级成"同一浏览器多标签"
```

想带上聊天室（需要一个本地服务）：

```bash
node server.js
# 打开 http://127.0.0.1:5210/
```

Windows 上双击 `启动网页版.bat` 即可（没装 Node 时它会自动改为直接打开静态页）。

### 桌面版

```bash
npm install
npm start          # 开发运行
npm run dist       # 打包成 Windows 安装包（输出到 dist-app/）
```

## 部署到 GitHub Pages

这个仓库可以直接当 Pages 站点用 —— 入口 `index.html` 就在根目录，而且**所有资源路径都是相对的**，挂在 `/仓库名/` 这样的子路径下不会 404。

```bash
# 1) 推到 GitHub
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main

# 2) 仓库 Settings → Pages → Source 选 "Deploy from a branch"
#    Branch 选 main，目录选 / (root)，保存
# 3) 等一两分钟，访问 https://<你的用户名>.github.io/<仓库名>/
```

仓库里带了一个 `.nojekyll` 文件，作用是让 Pages 原样输出、不要套 Jekyll 处理。

> 静态托管上没有后端，所以**茶室里只有"同一浏览器多标签"这一档能用**。
> 站点会自动判断：公网域名下不会去请求聊天室接口（避免在控制台留下 404），
> 只有本机 / 内网地址才会去找服务端。

## 桌面版

桌面版是同一套页面的 Electron 壳，多出来的是：

- **数据落盘**，不依赖浏览器存储。位置：`%APPDATA%\elemental-journal\data\`
  （`store.json` 站点数据、`chat.json` 房间码、`chat-history.json` 聊天记录、`chat-blobs\` 头像与表情）
- **菜单栏「茶室」**：开关局域网访问、查看/更换房间码
- 系统原生文件对话框（导入音乐、ICS、选图）
- 完全离线可用

打包产物与更详细的使用说明见 releases 或发布包里的 `说明.md`。

## 自定义（几乎全部内容都能就地改）

设计原则是**所见即可改**：鼠标移上去会浮出 ✎ 的文字，点一下就能编辑，改完自动存在本地。

| 位置 | 能改什么 |
|---|---|
| 首页主 / 副标题 | 大标题与两行副标题 |
| 左侧「个人资料」 | 头像、名字、签名（打字机那句）、下面那排平台标签（名称 + 链接，可增删） |
| 左栏「公告」「标签」 | 每条都能改，能 ＋ / × |
| 右栏「目录」「分类」 | 名称与计数都能改 |
| 场景序列 | 每条可增删改，还能搜 |
| 首页「记忆」段落 | 鼠标移上去浮出换图条，会写明"正在改第几幕、照片墙哪几张跟着换" |
| 手记 | 首页那几张卡片就是文章数据源；正文在 `enhance.js` 的 `ARTICLE_BODIES` |
| 作品集 | 封面、标题、类型、时间、简介，可增删、可按类型筛 |
| 项目 | 文字 / 图片 / 视频三种块，可加、删、上下移动；正文能内嵌 B 站 / YouTube |
| 自述 | 身份档案 / 时间线 / 兴趣 / 在玩的游戏 / 近况，全部可增删改，兴趣卡还能换图 |
| 友链 | 名称 / 简介 / 链接，可增删 |
| 茶室 | 昵称、头像、表情包 |
| 壁纸与背景 | 换成自己的图：首页第二幕的换图控件、「关于」页的头像框都能换 |

**想改默认文案（改代码给所有人看的那份）**：种子数据都在 `enhance.js` 与 `index.html` 里，
搜 `seed` / `data-ed-default` 就能找到；改完之后清一次浏览器本地存储即可看到新默认值。

## 聊天室

- **头像**：点侧栏自己那个圆点或「换头像」，选图后自动缩到 256px 再上传，别人立刻能看到
- **表情包 / 动图**：输入框左边的 ☺ 打开面板 —— 10 张内置贴纸 + 「＋ 导入表情包」+「＋ 导入动图」。
  动图**原样存原样发**，不会被压成静图
- **房间码**：桌面版在「茶室」菜单里看；网页版（局域网模式）在服务窗口里
- **历史**：桌面版存磁盘，网页版存 `网页版/.chat-data/`

传输上做了**两条通道并自动降级**：

| 通道 | 什么时候用 | 能力 |
|---|---|---|
| `lan` | 检测到本机/内网有茶室服务 | 真局域网，跨设备，SSE 推送，房间码，历史落盘 |
| `local` | 其它情况（静态托管、`file://`） | 同一浏览器多标签互聊，用 BroadcastChannel + localStorage |

服务端（`chatd.js`）是**零第三方依赖**的：SSE 推送、内容寻址的图片存储、房间码、限速、上传校验都是手写的。
并发上做了：消息由服务端发单调序号、客户端按序号定序去重、发现跳号自动补拉、
同 token 重连不产生幽灵成员、慢客户端背压踢出。

## 性能

桌面版实测（Intel 核显，显示缩放 150%，即 dpr 1.5，窗口 1426×883）：

| 指标 | 数值 |
|---|---|
| 持续帧率 | **215–240 fps**（贴着刷新率） |
| 帧时间中位数 | 4.2 ms |
| p95 / 最大 | 8.4 ms / 12.5 ms |
| 卡顿帧（>16.7ms） | **0** |

按 `Ctrl+Shift+F` 可以浮出实时帧率表。

做得比较关键的几件事：

- 统一的 rAF 调度器：页面隐藏时整体停机；**没有任何订阅者时彻底停掉 rAF**
- 自定义光标收敛后自动停帧，并给它独立合成层（否则每帧都在牵连整页重绘）
- 环境动效（花瓣 / 萤火 / 弹幕）限制在 30fps 绘制，用时间门限而不是隔帧丢弃
- 壁纸用两层交叉淡入，而不是换 `src`（`src` 不可过渡，换它就是硬切）
- **全屏壁纸默认不加滤镜** —— 全屏图上的 `filter` 会让这一层多走一遍光栅化，
  实测帧时间中位数从 4.2ms 涨到 12.4ms，而 1px 模糊肉眼几乎看不出
- 去掉了"为了显示一个 fps 数字而常驻的帧循环"
- 性能标定会把"GPU 进程还没就绪、正在软件光栅化"的启动期排除掉，
  不会拿那段假象当基准去永久削减特效

整站帧内 JS 约 **0.12ms/帧**。

## 项目结构

```
.
├── index.html          页面骨架 + 大部分基础样式（设计令牌、三栏网格、壁纸、横幅）
├── enhance.js          运行时层：开场、滚动叙事、路由、可编辑系统、游戏、粒子层、性能探针
├── enhance.css         上述模块的样式
├── modules.js          侧栏组件：日历、天气、课表、音乐、统计、文章
├── modules.css
├── chat.js / chat.css  茶室客户端（两条传输通道 + 界面）
├── chatd.js            茶室服务端（SSE + 上传 + 房间码 + 限速，零第三方依赖）
├── qr.js               二维码生成（字节模式 / 纠错 L / 版本 1–10，用于邀请扫码）
├── server.js           网页版的本地静态服务，同时把茶室接口挂上去
├── electron/           桌面壳：主进程（本地服务 + 数据落盘 + IPC）与 preload 桥
├── assets/             背景图、头像、图标
└── .nojekyll           让 GitHub Pages 原样输出，不套 Jekyll
```

## 技术上的取舍

几个刻意的选择，都写在了代码注释里：

- **零构建**：没有打包器，改完刷新就见效。代价是没有模块系统，靠 `window.MJ2*` 暴露。
- **SSE 而不是 WebSocket**：Node 原生 `http` 就能做，**不需要任何第三方依赖**，
  而且 `EventSource` 自带断线重连，省掉一整套重连状态机。
- **内容寻址的图片存储**：文件名就是内容的 sha1 —— 同一张图重复上传只占一份空间，
  并发上传同一张也不会互相覆盖，天然幂等，不需要加锁。
- **动图不重编码**：过一遍 canvas 动画就只剩第一帧，所以原样存原样发。
- **数据放在元组 / 对象里而不是外挂按下标索引的表**：条目增删时下标会整体平移，
  外挂表一定会错位。
- **不用 `filter` 做全屏装饰**：那是桌面版帧率问题的主要来源。

### 本站做过哪些差异化

参考"设计系统的做法"和"看起来像某个主题"是两回事。为了让源码层面也一眼看得出
是两个不同的东西，这里做了这些事：

| 做了什么 | 结果 |
| --- | --- |
| 设计令牌换成本站自己的词汇 | 纸 / 墨 / 印章三组（`--paper-card`、`--ink-strong`、`--stamp-bg`…），不再有和别人逐字同名的变量 |
| 类名换成本站自己的词汇 | `.sheet`（卡片）、`.enter-rise`（入场）、`.float-sheet`（浮层）、`.outline-cards`（描边开关） |
| 素材全部自己生成 | `assets/paper/` 下 14 个程序化生成的 SVG，不依赖任何第三方图片 |
| 横幅下沿换掉 | 由常驻的波浪动画换成静态的手帐撕口 + 缝线，同时少一个合成层 |
| 注释里的出处收口 | 不再逐条指名引用别人的文件名 / 类名，出处统一放在这一节 |
| **外形尺度整组换掉** | 见下表：顶栏高度、封面高度、四档圆角全部改成自己的值 |
| **版式骨架换掉** | 由"左右对称两条小组件栏"改成"一张主页面 + 一条页边"，见下 |
| **三个共有部件改了形态** | 自绘光标 / 设置面板 / 底部状态栏，见下 |

### 版式骨架：为什么不再是左右两栏

改之前是 `17.5rem / 1fr / 17.5rem` 的对称三栏 —— 也就是"大图封面 + 左右各一列
小组件"这一类骨架，和参考主题是同一个模子。现在是主页面在左、**一条** 240px
的页边在右，所有小部件收进这一条栏，另外用一条横向的"本站仪器"带
（使用情况 / 天气 / 日历）承担"一眼扫过"的信息。

| 版式 | Firefly | Mizuki | Yuimi | 本站（现在） |
| --- | --- | --- | --- | --- |
| 左侧栏 | 2 条 | 2 条 | 1 条 | **0 条** |
| 右侧栏 | 3 条 | 4 条 | 0 条 | **1 条** |
| 栏宽 | 320px | 280–320px | 约 300px | **240px** |
| 仪表位置 | 栏内 | 栏内 | 栏内 | **正文下方横向一条** |

页边是 sticky + 内部滚动的：11 张小部件竖排有 3600 多 px，让它撑开整页会
把页面拉到 6000px、正文旁边空出一大片；这样页面高度只由正文决定
（实测 3699px），页边自己滚自己的。窄屏（≤1279px）页边转为正文下方的
自适应网格，不再并排。

### 界面与版式的相似性，会不会构成侵权？

不会，而这些参考项目的条款里也没有任何一条这样声称。逐条看它们到底管什么：

| 项目 | 许可覆盖的对象 | 与"版式 / 界面设计"有关的内容 |
| --- | --- | --- |
| Fuwari | MIT —— 覆盖 "the Software"（代码） | 没有关于设计或版式的条款 |
| Firefly | MIT（`2024 saicaca` + `2025 CuteLeaf`） | 仅一句**请求**：「如果你参考或使用了 Firefly 的组件设计和相关代码，请注明来自 Firefly」——措辞是"请"，不是许可条件；`Footer.astro` 里"请勿删除 Powered by"也只存在于源码注释里 |
| Mizuki | Apache-2.0 —— 覆盖代码本体 | 只要求保留许可文本 / NOTICE 并声明改动，不涉及版式设计 |
| XinghuisamaBlogs | CC BY-NC 4.0 —— 覆盖 "the Work" | 约束的是**复制与传播其作品（含改编物）**，不是"借鉴一种版式思路" |
| Yuimi-chaya | MIT（代码 / 样式）+ CC BY-NC-SA 4.0（文章）+ 素材排除 | README 里「不要把首页脚本、音频流程或角色彩蛋整体搬进新项目」是**二次开发建议**，不是许可条件，且指的是别整段搬脚本 |

这些条款实际约束的是三件事：**复制代码**（须保留版权与许可声明）、
**复制素材**（图片/角色美术/音乐/字体明确不在授权范围内 —— 这才是真正的风险点）、
以及 **CC BY-NC 的商用限制**。

至于"几条栏、封面多高、用不用环形光标"这类**通用版式思路**，不属于受保护的
表达，也没有任何一条条款声称限制它。所以本站保留现有版式是安全的；
真正必须守的是**署名**与**素材边界**，这两件分别落在本节和
[第三方素材说明](THIRD_PARTY_ASSETS.md) 里。

### 三个"辨识度最高"的部件：形态也顺手改了

这四个参考站各自都有几个一眼能认出来的部件，其中三个是**共有**的。
功能留着（它们本来就该有），形态换成了另一种做法 —— 这一条**不是条款要求的**
（见上一节：条款不限制版式与界面），属于"既然要动就动干净"：

| 部件 | 参考站的做法 | 本站现在的做法 |
| --- | --- | --- |
| 自绘光标 | 四个站**全都有**"细描边圆环 + 中心圆点"，hover 时环放大 | **默认关闭**（设置里可开）；开了也是"笔尖 + 墨晕"：一个不规则实心墨点配径向渐变的洇开，**没有圆环描边** |
| 设置面板 | Firefly / Mizuki：右下角一个圆形齿轮按钮 + 一块浮起来的小卡片 | 右边缘一枚**竖排的"设置"书签**（`writing-mode: vertical-rl`），点开从右侧滑出一整条抽屉，只有左边两角是圆的 |
| 应用状态栏 | XinghuisamaBlogs / Yuimi：**固定贴屏幕底边**的一整条 | 收进设置抽屉底部，成为一段「应用信息」（视图 / 数据量 / 帧率 / 导出导入都在），`position: static`，不再占屏幕底边 |

自绘光标默认关掉这件事，除了"不和四个站撞形态"，也顺带省掉了一个常驻的
每帧缓动循环（鼠标不动时本来就已停机，现在是彻底不启动）。

### 外形尺度：为什么是这几个数

这几个数不是随手挑的。把参考站的真实渲染结果量了一遍（同一段提取脚本跑在
五个站上、同一视口），发现有一批尺寸是**完全撞在一起**的——两站的圆角、
封面高度、顶栏高度一模一样，远看就是同一个骨架。于是整组重新定值：

| 令牌 | 参考站的值 | 本站 | |
| --- | --- | --- | --- |
| 顶栏高度 | Mizuki 72px / Yuimi 71px | **56px**（`--nav-h`） | 拉开 |
| 首页封面高 | Firefly 65vh / Mizuki 65vh / Yuimi 96vh | **44vh**（上限 560px） | 拉开 |
| 内页封面高 | Firefly 35vh / Mizuki 35vh | **26vh** | 拉开 |
| 卡片圆角 | Firefly 16px / Mizuki 16px / Yuimi 8px | **22px** | 拉开 |
| 按钮圆角 | 8px | **10px** | 拉开 |
| 封面圆角 | 12px | **14px** | 拉开 |
| 小标签圆角 | 6px | **4px** | 拉开 |
| 卡片描边 / 阴影 | 32–100% 带描边和阴影 | **0% 描边、12% 阴影** | 本来就不同 |

`--nav-h` 是单独抽出来的令牌：记忆区的 sticky 偏移、阅读进度条、主网格的
负上移都跟它对齐，改一处全跟着走，不会出现"改了顶栏高度、别处没跟上"。

两处**故意没改**，说明理由：正文字号仍是 16px（这是浏览器默认值，几乎所有
站点都是 16px，改它没有实际的去雷同价值，却要冒整体重排的风险）；
`oklch + 裸数值色相` 这套**做法**仍与 Fuwari 同源，但变量名与取值已经是
我们自己的——属于"同一类思路"而不是同一套实现。

两处改名都是**纯改名**，画面没有任何变化——这点不是估计，是量过的：
同一套「按 DOM 位置取 15 条绘制属性」的指纹，在 9 个路由上改名前后的结果
逐字节相同（令牌那轮 `efadeb1f`，类名那轮 `b9d32088`）。
